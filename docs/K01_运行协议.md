## 3. 文件与字段

路径相对于项目根目录，UTF-8，CSV 第一行为字段名。多 ID 字段用 `|` 分隔；ID 分配后不复用。四类名称仍为 normal、inner_race、outer_race、rolling_element，但本版只建立一个 outer_race 情景。三任务名称固定为 explanation、inspection、preparation。

| 表 | 关键字段与解释 |
| --- | --- |
| sources.csv | `source_id` 主键；title、organization_author、version_or_date、original_url、access_date、timezone；format、page_or_section、applicability；full_text_status 说明取得/阅读范围；local_path、sha256、local_copy_status、access_limitations、rights_use、reviewed_by |
| scenarios.csv | `scenario_id` 主键；predicted_class、class_semantics；assumed_cause、assumption_text；known_conditions、unknown_information、applicability、cannot_infer；supporting_evidence_ids、support_meaning、task_types、status |
| evidence.csv | `evidence_id` 主键；source_id、knowledge_id、task_type；source_url/source_version 与来源登记一致；pdf_file_page、printed_page、page_or_section；original_text、chinese_paraphrase、claim_en；conditions、limitations、modality、applicability、reviewed_by |
| entities.csv | `entity_id` 主键；entity_type 为 part/scenario/assumption/mechanism/task/knowledge/evidence；label 为标签；content_ref 指向表内内容，项目部位和任务使用明确的 project_*_contract |
| relations.csv | `relation_id` 主键；subject_id、relation、object_id；assertion_basis 区分事实/假设/组织；evidence_id、conditions、limitations、semantic_note |

实体表中的 evidence 节点 ID 与证据表主键有意相同，是同一个对象的索引，不算重复实体。其 content_ref 必须回指自身证据；知识实体必须回指 evidence.knowledge_id 绑定的证据；MECH-K01-FB 明确回指 EV-K01-002，不能仅检查目标存在。知识实体的内容由对应证据行承载；不另建图数据库。

PDF 文件页序从 1 开始，印刷页码单列，不能用浏览工具的从 0 开始页索引直接填写。HTML 不编造 PDF 页码，两个页码字段留空，用标题/段落/步骤定位。没有本地文件时 local_path/sha256 必须同时空白且写明取得状态与原因；未取得全文的内容不作为证据。本次 Timken 全文在线可读，核查相关页面，未本地下载，不能冒称离线已完整保存。

`original_text` 是必要的英文短摘录，每一来源总量控制在 25 个英文空格分词以内；`; ` 表示分开的短摘录，不冒充原文连续句。`claim_en` 是项目 agent 整理的英文概括，`chinese_paraphrase` 为中文释义，两者都不是原文引语，也不代表人类或专家签核。短摘录用于定位，完整支持程度须连同出处的完整段落核查。不可把关键词存在当成主张成立。

`modality` 保留 reported_example、possible_cause、alternative_possibilities、inspection_cue、inspection_guidance、preparation_guidance、scope_constraint、sequence_constraint 的差别。具体取值见表；通用适用范围固定为 generic_bearing_education_only。

## 4. 关系语义

| assertion_basis | 关系 | 证据要求 |
| --- | --- | --- |
| project_contract | routes_from_class、has_task | 项目路由/任务组织，不声称物理事实，evidence_id 空白 |
| demo_assumption | assumes_for_demo | 仅独立假设，evidence_id 空白，不伪装来源证明 |
| source_knowledge | has_reported_example | 来源给出案例，不能改写成普遍结论 |
| source_knowledge | is_possible_cause_of | 保留可能性、静止/小幅运动条件，禁止升级为确定个案根因 |
| source_knowledge | has_evidence_backed_content、supported_by | 任务到知识及知识到证据，必须有能支持内容的 evidence_id |

每条来源知识关系的条件与局限必须随证据一同保留。任务分类由项目 agent 组织；来源支持的是知识内容，而不是宣称制造商定义了项目任务分类。EV-K01-010 的检查范围和五项评价因素必须连同“非完整复用判据、须核拒用条款和适用文件”的限制传播至 REL-K01-026/027。

## 5. 验收分工与重跑

`scripts/validate_k01.py` 检查固定字段、ID、引用、镜像的精确对应、边/节点类型、来源元数据、三任务覆盖、引用长度、本地原文字节和摘录存在性，并核对接口的允许/禁止输入集合、表名、版本和身份描述等。13 个原有内存反例继续检验拒绝路径；`tests/test_k01_validation.py` 回归新发现的错连和接口矛盾，包括实际 CLI 的隔离目录检查。不修改正式知识表。结构成功不意味着语义成功，也不能排除自由文本里隐藏答案。

rev010 的 `manual_review.csv`（11 条证据）、`relation_review.csv`（29 条关系）及 `manual_review_binding.json` 只绑定当时表格；独立交叉审核另有逐条审查。rev011 的 `semantic_delta_review.csv` 重新对照 EV010、REL026/027，`semantic_binding.json` 绑定最终五表并逐行证明其余 37 条证据/关系未变，明确沿用旧审核依据而非声称本轮重审全部来源。检查条件、否定、例外、适用对象、顺序、因果强度及 task 相关性；署名为项目 agent 对照，不虚构第二人或专家核准。历史语义反例仍是“结构可通过、原文对照应拒绝”；它们不是 E01 题集或模型效果实验。

从根目录激活已有环境后，可用一个不存在的新输出路径只读重验：

```bash
PYTHONDONTWRITEBYTECODE=1 python scripts/validate_k01.py \
  --output /tmp/k01_recheck_unique.json
```

脚本以独占方式创建结果；路径存在会拒绝，需换新名称。`--knowledge` 指向隔离副本时校验该目录自己的 interface.json；来源原件仍按登记路径在项目根目录只读核对。不要重跑历史 build_tables.py、record_manual_review.py、semantic_examples.py、seal_revision.py 来覆盖已归档证据或重建当前表格。rev010 的命令/网络记录保留历史事实，rev011 命令及验收见 `runs/k01_fix/rev011/commands.md` 和修复说明。
