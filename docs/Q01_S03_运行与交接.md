# Q01-S03 英文任务识别规则基线：运行与交接

当前q01.tasks.rules.v1仅完成离线规则基线与输入接线。本轮不需要用户提供额外密钥/模型/费用权限，不读取已有密钥；实际API0、真实K02运行0。它不是通用自然语言理解或已验证的语义分类模型，也没有LLM任务识别服务。

## 接口与边界

scripts/q01_tasks.py的recognize_tasks(question)只做识别；prepare_request(payload)接受predicted_class、scenario_id、question、explicitly_allowed_operating_context四字段，全部分句明确时加task_types（explanation/inspection/preparation，去重/固定顺序）。原始四字段保持，类别/情景/工况仍由调用者显式提供，不从问题推断根因或真实分类。

route_and_run(payload,config,provider,retriever=...,runtime=...)仅ready时调用旧flow一次。外层routing元数据不传模型；flow_record保持旧失败/预算/发布控制。ready是句式/结构可路由，不代表语义或维护正确。旧五字段请求/实验task_types继续用原run_flow；本适配器拒绝额外task_types/评价身份/答案字段，不覆盖冻结任务标签。

当前只认ASCII英文、最长2000字符、最多6明确正向分句，每分句需显式轴承/维护词或this result/label；按问号/分号/换行/and等拆分。支持why/meaning解释、inspect/check及被动检查问句、prepare/preparation等固定前缀。命中规则ID/分句索引可读，无伪造概率。any未识别分句不发布部分task列表；无匹配/否定/引号/备选等needs_clarification，领域或任务越界unsupported，结构/类型/Unicode错误invalid_input，均无运行请求。

这是保守启发式：对象中and、自然缩写/引号/否定条件、同义转述和省略领域词等可能请求澄清；词匹配不能识别全部伪装越界/恶意自由文本。CONTROL检查不是安全沙箱或语义证明。后续可另设计LLM任务识别，但须独立合同/资料隔离/计数/预算，不能重用S02已消耗真实批次。

## 入口

Python复用prepare_request与route_and_run即可，无网络或语料导入动作。CLI只输出任务识别记录，不自动检索/调用provider：

```text
python scripts/q01_tasks.py --input runs/q01_task/<新run>/inputs/question.json --output runs/q01_task/<新run>/outputs/routing.json
```

先创建不存在的新run及输入/输出子目录；不要用本已封存run重跑。CLI路径只允许runs/q01_task内，拒绝任一级符号链接；输出先独占创建再读输入，已存在不覆盖；输入最多64KiB、严格JSON/重复键拒绝。ready退出0、受控非ready退出1、路径/独占写失败退出2；坏输入也保存可记录诊断。测试原件入口和oracle不改，Q01_TASK_RUN_DIR/Q01_RUN_DIR必须指向新输出。
