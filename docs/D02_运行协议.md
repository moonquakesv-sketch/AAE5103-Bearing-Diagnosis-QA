## 2. 实际执行顺序

1. 核对文件与信号 SHA-256，读取清单精确 DE 通道。`99.mat` 只读取 `X099_DE_time`。
2. 使用 `scripts/data_contract.py` 的同一重采样实现。正常 48k→12k、故障 12k→12k；整条记录处理后两端各剔除 128 点，再生成 2048 点无重叠窗口。索引为完整重采样信号的零起点、左闭右开区间，首窗 `[128,2176)`。
3. 仅从训练记录 97／105／130／118 各取首个有效窗口试跑；已知频率合成信号检查填充裁剪、频率坐标、时间／频率方向和确定性。试跑预览的逐图分位数仅用于观察管线，保存于 `pilot/`，不进入正式样本或公共颜色范围。
4. 确定全部训练有效窗，再按各训练记录有效窗数的最小值平衡，使用 `floor(linspace(0,n-1,m))` 选择。保留有效窗、剔除窗及最终选择索引。
5. 从完整平衡训练部分的原尺寸 float64 log-power 矩阵拟合公共分位数，再生成训练图。保存训练矩阵、训练清单、颜色范围、频率向量和输入／代码／图片哈希，写入 `training_freeze.json`。
6. 冻结通过后，验证／测试保留全部有效完整窗，复用训练颜色范围机械生成两类图。`heldout_generation.json` 记录开始时间晚于训练冻结、颜色文件前后哈希相同、颜色拟合调用次数为零。
7. 独立验收全部元数据、片段、图片格式和像素哈希，重新计算训练分位数，并从每条原记录的首末样本重复生成矩阵和模型图像素。

`configs/data.yaml` 保留 D01 的候选配置原字节，便于历史追溯；本轮未改变其任何数值参数，正式冻结状态以 D02 的 `training_freeze.json` 为准。试跑期间将复核图改为固定坐标区域以保证留白，未改 CWT、窗口或颜色算法，因此保留处理版本 `v0.1`。早期预览完整保存在 `pilot_attempt01/`，最终预览和评审见 `pilot/`、`pilot_review.json`。验证／测试未参与这一决定。

## 3. 颜色、坐标与图像语义

CWT 使用 `cmor1.5-1.0`、FFT、precision 12、100–3000 Hz 的 128 个对数等距频点、左右反射填充各 1024 点后裁回 2048 点。每窗减均值，幅值不做逐窗标准化。log-power 为 `10*log10(max(abs(coef)**2,1e-12))`，未标定为物理 PSD。

公共颜色范围由 232 个训练窗、60,817,408 个原尺寸矩阵元素拟合，`numpy.quantile(method='linear')` 的 1%／99% 分位数为：

- `vmin = -48.37472311262306`
- `vmax = -8.743731319098826`

完整拟合窗口 ID、矩阵哈希、输入和代码哈希、分位数方法及时间保存在 `configs/cwt_color_limits.json`。训练 float64 矩阵位于 `runs/d02/cwru_de_007_v0.1/train_matrices/`，支持直接重算分位数。验证／测试不参与拟合，不逐图自动拉伸。

模型图先把升序频率矩阵上下反转，以 Pillow F 模式 BILINEAR 缩至 224×224，再裁剪到公共范围、应用 viridis 并量化为 RGB PNG；图内只有数据，无轴、边框或类别。复核图使用同一原矩阵和颜色上下限，在 640×420 画布显示时间轴、真实对数频率轴及颜色标尺。复核图的频率边界是频率中心的几何中点，并保存实际中心向量 `frequencies_hz.npy`。两类图的标量来源和颜色相同，显示分辨率与绘图方式不同，不要求截图像素逐一相等。

最高频率在上，时间向右。合成信号左半为 300 Hz、右半为 1500 Hz，峰值约 291.901／1495.266 Hz，模型图峰值行分别为 152／46，与对数频率位置相符。复核只查看了合成图和训练图，未人工查看验证／测试图。


从现有交付完整重复训练颜色拟合、全部图片生成和验收的一条命令：

```bash
python scripts/reproduce_d02.py --compatibility runs/d02_fix/rev005/compatibility.json --output-root /private/tmp/aae5103-d02-rev005-reproduction-new
```

输出目录必须不存在且位于原项目之外。程序复制冻结输入、代码及已通过的训练试跑评审，原始 MAT 以只读用途的符号链接复用，不重新下载或划分；在新目录从训练部分重新拟合颜色，再生成所有图片和验收日志。最后比较 704 个样本的索引、CWT 数组哈希、分位数和拟合成员，并直接读取来源与新目录的全部模型图、复核图，比较解码像素。复核图路径相同不再被当作内容相同。复现会占用约 0.7 GiB，运行数分钟；目录名已存在时应换新名字，不能覆盖旧复现。

验收区分数值／解码像素一致与文件字节一致：时间戳会使颜色 JSON 及其下游记录的文件哈希变化，复核 PNG 在不同绘图库版本中也可能改变；修订 005 验证的目标是相同配置和依赖下的全部 CWT 数值、模型图像素及复核图像素；跨版本绘图库可能不满足逐像素一致，需另行评估。最终交付的具体文件字节另由阶段 SHA-256 清单保护。

修订 004 曾实际执行一次完整新目录复现，704 个样本的索引、矩阵哈希及模型图像素全部一致，训练颜色分位数、拟合成员和矩阵哈希也完全一致。必要证据已复制到交付目录的 `reproduction_comparison.json`、`reproduction_acceptance.json`、`reproduction_training_freeze.json`、`reproduction_color_limits.json`，完整输出见 `reproduction.log`。交接不依赖系统临时目录继续存在。

使用新阶段冻结清单复验 D01 语义与交接字节：

```bash

```

D01 验收默认写入新的 `runs/d01_checks/`，可用 `--output` 指定不存在的文件。当前 D02 内容复验命令为：

```bash
python scripts/d02_pipeline.py validate --compatibility runs/d02_fix/rev005/compatibility.json --output runs/d02_fix/rev005/recheck-new.json
```

输出文件必须不存在。当前验收逐行核对完整预期样本集合，再从原始 MAT 重算全部 704 个 CWT，在临时目录重建两类图并比较实际解码像素；分别报告模型和复核图结果。合成方向检查读取实际 RGB 输出及保存后的 PNG，并检查复核图的对数频率显示坐标。

`compatibility.json` 是显式的验收代码变更登记，不是重新拟合或重新冻结：它绑定旧训练冻结、旧输入哈希、已批准的新代码哈希和旧代码备份，只允许 `d02_pipeline.py` 这一输入发生已登记变化，并检查 10 个数值处理／绘图函数 AST 不变。其他配置、清单、来源代码或训练产物变化仍被拒绝。未指定登记文件时，旧冻结与新代码不一致会继续失败；不得关闭校验或改写旧冻结。新目录复现保留已批准的训练试跑证据，重新执行实际 RGB／复核坐标检查后再拟合训练颜色、冻结及生成保留集合。
