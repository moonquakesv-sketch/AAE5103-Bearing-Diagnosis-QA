# K02 两种检索基线运行协议

当前实现版本 `k02.v1_rev013`；知识仍为 `20261023_rev011`。本阶段只检索资料，不生成答案、不核验自由文本语义，也不接分类器、LLM/API或网页。初版运行现场为 `runs/k02/20261024_135147_4d6ea8a8/`；独立审核后的 A01/C01 修复现场为 `runs/k02_fix/rev013/`，说明见 [K02_修复说明](K02_修复说明.md)。下文原索引及开发验证记录指初版现场，原字节保留。

## 1. 固定语料与公平对照

实现约定在初版调试之前保存在原运行目录的 `implementation_contract.json`；固定配置为 `configs/k02_retrieval.json`。rev013 只更新配置中的实现版本身份，检索参数及知识哈希不变；当前同字节副本为 `runs/k02_fix/rev013/config_snapshot.json`，初版 `config_snapshot.json` 保留 rev012 历史。没有术语映射、配置搜索或按开发问题重新拟合。

加载器只读取 `knowledge/k01/` 的五张CSV与interface.json，逐文件核对代码固定的rev011 SHA-256，再用当前K01校验函数检查字段、引用及精确镜像。校验和解析使用同一次读取的字节。未知文件不会被扫描；原始HTML、runs、主计划、审核表、反例、测试断言和评分材料均不入索引。厂家来源登记随结果返回；运行时不重新下载或索引原件。K01本地HTML的哈希/摘录检查曾在初版运行及后续独立审核中单独复验，不能把这些复验误写为每次检索都重新核对厂家原件。

每条证据为一张完整资料卡，共11张。索引文本严格为 `original_text + 换行 + claim_en`。前者是短原文摘录，后者是项目agent的英文概括，不是厂家原话或专家签核。中文释义、条件、限制、modality、applicability、出处和reviewed_by不参与英文词频评分，按原值返回。scenario、entities和relations用于共同上下文/组织关系，不作为额外证据文档拟合。

使用现有scikit-learn的TfidfVectorizer：小写、Unicode去重音、正则 `(?u)\b[a-zA-Z][a-zA-Z]+\b`、内置英文停用词、单词unigram、原始词频、smooth IDF、L2归一化。IDF只由固定11张卡拟合；每次查询只transform。余弦分数大于0才可返回。同分规则是分数四舍五入至12位后降序、evidence_id升序，输出仍保留原始浮点分数。128个词项及实际文档、IDF、矩阵可在 `index_snapshot.json` 检查；运行包版本见 `environment.json`。

两组用同一完整英文问题，追加同一类别（下划线改空格）、情景 `assumed_cause`（下划线改空格）、规范顺序的任务标签、按键排序的允许工况值。`query_text`明确保存实际评分文本。两组均获得同一完整情景、假设、未知信息及来源资料；区别仅在候选集合：

- **text：** 所有11张证据卡直接评分，不使用关系筛选或task_type过滤。
- **graph：** 用部位节点反向查询 `routes_from_class` 找调用方选定情景，再正向沿 `has_task → has_evidence_backed_content → supported_by` 找到证据。按实际边筛选后使用同一矩阵和同一查询分数。没有按问题硬编码evidence_id。

`routes_from_class` 在表中是“情景→部位”；结果的第一步因此标为reverse。每个候选的完整路径保存节点、方向及原关系行，包括该边条件、限制、assertion_basis。`assumes_for_demo`和`is_possible_cause_of`不被当作事实推导规则；遍历只组织资料。生产加载器拒绝修改后的K01；合成断边/改接实验只能走隔离的纯遍历函数，不能作为生产知识导入。

## 2. 业务输入与配置

Python入口：`scripts/retrieve_k02.py` 中 `Retriever(...).retrieve(request, mode='text', top_k=3)`。合法请求必须恰有以下五个字段：

| 字段 | 运行时约束 |
| --- | --- |
| predicted_class | 字符串，normal/inner_race/outer_race/rolling_element之一；只是调用方类别，不验证预测真实性 |
| scenario_id | 非空字符串；当前仅SC-K01-OR-001可覆盖。存在情景但类别不符则报class_scenario_conflict；不存在情景返回knowledge_not_covered |
| question | 字符串；正常开发样例使用完整英文问题。空白、无分析词项、问题本身无固定词表词项分别返回明确状态 |
| task_types | 非空、无重复的字符串列表，值仅explanation/inspection/preparation；由调用方显式给定 |
| explicitly_allowed_operating_context | 字典，可为空；允许键和枚举见下，不允许任意嵌套、备注或其他键 |

允许工况键：`operating_state`只能是`unknown`或`standstill`；`external_vibration`只能是`unknown`或`assumed_for_demo`。这些值只描述演示设定或调用方未提供的信息，不能表示实测工况。`unknown`不撤销所选情景中明确标注的演示假设。空字典表示调用方未额外提供工况。旋转工况、实测振动值、型号、路径和任意备注本阶段均不接收。

明确禁止ground_truth、true_label、样本编号/文件名/路径、含答案备注、评分答案与规则；白名单外所有未知字段一律拒绝，包括把retrieval_mode/top_k混入业务请求。JSON重复键和非有限数字拒绝。返回错误不回显越界请求值。Python 业务输入校验失败抛出带 code 的 K02Error；predicted_class、scenario_id、question 含无法编码为 UTF-8 的代理码时返回 invalid_unicode。合法 Unicode 字符及 JSON 中正确配对并解码后的补充字符仍可使用。文件不存在等 I/O 错误由 Python 调用方处理；CLI 在参数解析成功且输出文件可创建时，为请求/知识/配置处理错误写入完整的结构化 rejected 记录。

CLI 参数语法错误另由 argparse 处理，例如 `--mode alien`、`--top-k 2.5` 或缺少必需参数：退出 2，仅 stderr 有 usage/error，**不创建结果文件，也没有 JSON error_code**。`--top-k 0` 则能通过整数语法解析，随后写 rejected/invalid_budget 并退出 2。已有输出或无法创建/写入输出时，通过 stderr 的 output_rejected 报告，不能假定存在可读取的结果 JSON。调用方须结合退出码、stderr 和结果文件是否完整可解析来处理失败。

`mode`和`top_k`是独立运行参数。top_k为1–11整数，拒绝布尔值，默认3。`--config`只能使用内容等于当前固定配置的文件；任意改参数或知识哈希需作为未来版本另行授权、记录和检查。本实现不接受加载时临时解除哈希约束。

字段白名单只防明确的字段级越界。它不判定自由文本是不是英语完整句子，不自动识别所有隐藏答案、错误前提或伪装信息；不应将它称为全面防泄漏或语义安全检测。

## 3. 预算、任务状态与完整输出

预算按**完整证据卡数量**计，不按字符/token截断；没有长度上限，也没有文本概括替换。候选按evidence_id去重，全局排序后取前top_k。多任务没有保留配额或补位：某任务可能被其他任务的高分卡挤出。两组预算分配相同，返回长度可以不同，应在未来E01/生成设计时另行固定长度控制方案，不在本轮临时调参。

`per_task`按证据卡原task_type统计，不把任意跨任务文本匹配说成该任务已回答。状态包括retrieved、no_candidates、zero_similarity、budget_exhausted。整体可能为retrieved或partial_task_coverage；空问题、无词项、无词表词、未覆盖情景和无候选有独立状态。零分永不填充top_k，剩余预算明确记录。问题本身无有效词表项时，在加入情景上下文之前停止，避免上下文替无关问题制造检索命中。

每条返回卡保留全部原evidence字段，另加rank、score、完整source登记和relation_paths；因此原文、英文概括、中文释义、条件、限制、modality、applicability、来源URL/版本/文件页/印刷页/小节、原件取得限制都不会因预算消失。source.local_path是合法的厂家来源追溯信息，与禁止的分类样本路径不同。所有成功/空结果保留请求、配置身份、知识版本、假设与未知信息、能力边界提示；图谱路径保留所有候选，便于核查选择过程。

分数只是文本相似度，不是正确概率、根因概率或维修置信度。retrieved只说明有资料卡返回，不说明回答充分、语义通过或可以执行维修。

## 4. 离线运行与验证

复用已有aae5103环境，设置 `PYTHONDONTWRITEBYTECODE=1`，不安装依赖。示例从项目根目录运行；输出名必须不存在：

```bash
PYTHONDONTWRITEBYTECODE=1 python scripts/retrieve_k02.py \
  --request runs/k02/20261024_135147_4d6ea8a8/inputs/inspection.json \
  --mode graph --top-k 3 --output /tmp/k02_inspection_unique.json
```

text模式仅更换`--mode text`，使用相同请求与预算。正常的检索/空结果/未覆盖状态退出码为0；非法输入、知识漂移或写入失败为2，输出形式区别见第2节。输出用`open('xb')`独占创建；已有文件或悬空符号链接均不会覆盖。成功结果先在内存中完成 JSON 序列化和 UTF-8 编码，错误结果使用安全的 ASCII 转义，再写入内容；编码失败不会留下半份结果 JSON。stderr/stdout 的 JSON 状态摘要也使用 ASCII 转义，中文路径仍可按 JSON 正确解码。这不保证断电、磁盘写满等 I/O 中断时的文件事务完整性。父目录须存在；调用方应选择新的K02运行目录。

```python
import sys
sys.path.insert(0, 'scripts')
from retrieve_k02 import Retriever
engine = Retriever()  # 每个实例只在固定证据语料上拟合一次
text_result = engine.retrieve(request, mode='text', top_k=3)
graph_result = engine.retrieve(request, mode='graph', top_k=3)
```

回归只选择K02测试，不运行整个分类项目测试集：

```bash
PYTHONDONTWRITEBYTECODE=1 K02_TEST_RUN=runs/k02/<新的审核目录> \
  python -m unittest discover -s tests -p test_k02_retrieval.py -v
```

先建立新审核目录并做保护；不要向已封存目录重跑。旧K01测试中有一项硬编码历史临时目录，初版运行排除了它并选跑另10项只读回归，当时的K01 CLI结果、K02实际CLI与加载边界验证补充相关检查。初版执行记录见原现场 `commands.md`、测试日志及 `cli_checks.json`；独立数学/表格检查见 `independent_check.py`。后续独立审核已用隔离适配运行全部11项K01回归。rev013只运行K02的22项回归及修复反例，使用新修复目录内的测试适配副本，适配差异/日志在该目录；没有改K01或重跑分类测试。运行目录脚本及快照是历史执行证据，不能不改输出目录便重复执行。

## 5. 必须保留的解释边界

类别、独立演示假设、来源支持知识、仍未知信息分别返回。EV010只提供检查方向，不能单独决定复用、更换或放行。静止外部振动未被观察，润滑不良仍是另一种可能；实物表面纹理不能变为CWT判据。Timken证据卡可使用，但同版本地PDF/哈希与视觉核查仍缺失；旧access_limitations记录的是历史取得情况，本轮没有联网重试或补原件。

当前只支持一个outer_race情景。其他类别/不存在情景不会借用外圈卡冒充完整知识。不产生型号参数、航空指令或处置结论。K02完成后停止；独立审核和E01都需要用户下一步授权。
