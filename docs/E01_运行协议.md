# E01 问题集与评分规则：当前单情景版本

版本 `e01.single_scenario.v1_rev015`，日期2026-10-24（Asia/Hong_Kong）。本轮只完成评价准备，不运行检索效果比较、答案生成、语义核验或端到端实验。完整项目还需要其余情景的知识与对应评价准备；本单情景完成不代表全项目E01全部完成。

## 范围、设计与入口

固定设计先写入 `evaluation/e01/v1/design_contract.json`，之后才编写英文问题。共15题：10调试、5保留，按13个问题意图家族分组。调试8家族：可能机制、分类与根因边界、实物鉴别、清洁前证据保存、检查范围与复用边界、解释加检查、三任务概览、调查记录。保留5家族：润滑样品身份、拆卸规划前提、时间相关不等于因果、离线来源移交缺口、型号参数与航空适用缺口。一个家族只在一个划分内，不能把同一问题的近义改写分到两边。

数量来自独立请求目标，不追求大题数。正文包括单任务、多任务、条件/限制、假设与事实、错误前提、部分可答及证据不足。另有3个未覆盖类别/情景边界样例和8个合成非法接口样例；它们不进入正常15题的问答质量分母，不为其他类别编造正式知识答案。接口样例只通过新本地校验器检查，不调用K02。

业务与评价文件分开：

| 文件（evaluation/e01/v1/下） | 用途 |
| --- | --- |
| debug_requests.jsonl / heldout_requests.jsonl | 每行仅五字段业务请求；没有题ID、划分、评分或出处 |
| question_bindings.json | 评价侧ID、家族、划分、显式文件行号、规范请求哈希 |
| rubrics.json | 每题原子评分点、原值出处、支持组合、条件、未知、禁止推论和部分分 |
| boundary_cases.json / contract_cases.json | 未覆盖边界与合成接口反例，单独计数 |
| design_contract.json | 编题前设计、范围、数量及划分规则 |

`predicted_class`与`task_types`都是离线模块测试桩，不是实际分类器或任务识别器输出。本题集仅`outer_race`及`SC-K01-OR-001`，获准工况字典为空；空字典表示没有额外提供工况，不撤销情景中明确标注的独立演示假设。问题中的“如果/假如”是待判断前提，不是已采集设备观察。

## 开发暴露与保留题的真实含义

本轮对历史K02输入及开发代码作静态盘点，未读取排名输出来选题。详见本轮 `exposure_inventory.json` / `exposure_review.md`。182份输入文件和静态测试文字已登记；通用原因、实物纹理、检查/准备、清洁顺序及多任务总览均已暴露，所以放调试侧。五个保留窄意图未找到同目标的历史业务问句；它们仍共用此前全部暴露的11卡和限制，不能称全新知识或完全独立盲测。

保留题是为后续系统运行留出，编题agent和研究者能够阅读它们及评分资料。本轮不把任何真题交给Retriever或生成器，也不查看保留题系统结果；调试题也没有运行检索。五个保留题只支持此情景的未来配对描述比较，不能支持其他设备、故障类别、知识域或航空维修泛化。重复输出不是新的独立问题，多个题也不是多个独立设备。

## 评分依据与边界

以当前登记K01 `20261023_rev011`为评分依据，绑定K02 `k02.v1_rev013`。每点有完整/部分/0分判据。支持组合中内层为AND、外层为OR；满足任一完整替代组合即可，不能强求所有替代证据同时返回。相关词出现不等于结论有依据。当前真实题未预定“部分证据组合”，因此检索支持覆盖只按完整组合1或未满足0；回答文字可按逐点非关键遗漏给0.5，二者不可混用。

项目方法约定：来源登记和SHA-256哈希只核对登记状态与字节身份，不构成语义真实性证明。

rev015仅修复独立审核R-RUB-001/002/003，当前共15题68点。D010的因果警示不再是额外必答点；如果主动声称资料准备已经证明根因，仍登记禁止推论。D010维护记录点不设半分，核心维护记录缺失为0，不借用运行历史重复计分。H001必须未知仅为题目所问的采样量；采样方法、容器和实验室限制仍可作为选填缺口提示，不进入该题A_bound、i2必需项或题级完整判据，虚构容器等信息仍禁止，实际采样方法仍须遵循适用设备流程。

逐点`citations`完整复制登记证据原值，含evidence_id、knowledge_id、source_id、页码/小节、原文、概括、条件、限制及modality；`basis_refs`精确定位项目情景、来源登记或本方法约定。`explicitly_unsupported`表示应承认该请求缺乏依据，其“正确承认证据不足”可得边界分，绝不能当作支持该越界结论的正向知识。项目边界不得假装厂家结论。需原文再核实的争议标`needs_source_review`并挂起，不擅自补齐；本轮未重做厂家全文语义审核。

保留以下区别：调用方外圈类别不是已核实事实；停机外部振动是独立演示假设；假性布氏压痕是可能机制，润滑不良仍是其他可能性；EV-K01-010只给检查方向，不能单独决定复用、更换或放行；实际表面纹理不能由CWT图像替代；Timken同版本地PDF、哈希和视觉核查缺失；不提供型号参数、航空维修指令或处置结论。来源概括由agent编写，没有人类或领域专家签核。

每题单点分数为0/0.5/1；关键条件反转、假设升级成事实、处置越界均为0并登记错误。部分分只允许该点预定且保留关键条件的非关键细节遗漏，不可按篇幅折半。每题“完整”须所有要求点为1、必要条件/未知完整且无禁止推论；“部分”表示至少一个要求点有分但未完整；全点0为“不支持/未满足”。无依据主张、关键条件错误另报告，不能被平均分抵销。

每题另预定三个不足处理判据：i1拒绝无据结论/纠正错误前提，i2具体说明缺什么，i3保留可支持部分；若全无可答知识则明确未覆盖范围。完整1，承认方向正确但非关键细节不全0.5，空白/相反或服务失败0。对预定部分可答/错误前提/不足题启用；知识可答题若本次3卡实际不足，也启用同三项，仍扣掉未覆盖知识点，不能用合理弃答补成满知识分。完整可答且本次证据充分时全盘拒答计不必要弃答。

`conditions`列表是原子评分点应保留的条件；未来条件评分按实际表达内容确定适用项，每项保留1、缺失/反转0，本版不另授条件0.5。未知条目中并列内容均明确承认给1、只承认部分且不造假给0.5、未承认或反说0。完整/部分题级判别不能替代指标分子分母。指标、失败与缺失、零分母、重复及人工盲评详见 `docs/E01_指标与人工评分指南.md`。

## 实际检查与复用方式

使用既有aae5103环境，`PYTHONDONTWRITEBYTECODE=1`，不安装或升级依赖。新校验器 `scripts/validate_e01.py`只读取显式文件列表；导出器按ID映射到指定JSONL行，重新检查五字段并构造请求，不扫目录、不读取整行评分记录。合成测试把评分秘密放在相邻文件和元数据中，证明导出只含五字段；也验证真正混入业务请求的未知字段会被拒绝。字段白名单不能识别自由文本中的全部答案泄漏。

校验器实际运行与日志、合成坏例拒绝、指标合成计数复算、逐题登记知识对照、绑定与保护结果在本轮独立运行目录。所有运行输出必须写入新的不存在路径，禁止对历史运行目录执行生成/更新/封存脚本。本轮不运行全项目测试发现、不加载分类器或图像、不读取已消耗分类结果选题、不预测/提特征/拟合/evaluate/resume，不联网/API/网页，不进入Q01或情景扩展。

新机器可先按本轮 `verification_binding.json`与`deliverables.sha256`做只读字节检查，再运行新校验器并指定新的结果路径；不要重跑本轮authoring/封存脚本或覆盖本轮日志。校验器命令示例（输出必须不存在）：

```bash
PYTHONDONTWRITEBYTECODE=1 python scripts/validate_e01.py \
  --dataset evaluation/e01/v1 --output runs/e01/<新运行目录>/validation.json
```
