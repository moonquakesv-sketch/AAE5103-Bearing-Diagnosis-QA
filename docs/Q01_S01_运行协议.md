# Q01-S01：单情景离线问答流程

当前修复版本 `q01.offline.v1_rev017`，原rev016实现与审核证据保留。只验证代码接线、状态与失败处理，不验证真实模型质量、文本蕴含能力或图谱收益。K01保持rev011、K02保持rev013；E01评分仍rev015，全部真题禁止提交本流程。本协议不放行正式实验。两项有界修复及证据见 `Q01_S01_修复说明.md`、`runs/q01_fix/rev017/`。

## 范围与入口

入口为 `scripts/q01_flow.py`：`run_flow(request, group_config(group), provider, retriever=None)`，返回诊断字典，不自行写文件。默认使用真实K02；合成测试显式注入抽象retriever。provider只需实现`generate(payload)`、`verify(payload)`、`revise(payload)`。内置`ScriptedProvider`按固定动作队列返回对象或抛出异常，不理解文本，不访问网络，无SDK或新增依赖。

业务请求严格沿用K02的五字段与类型、枚举、空值约定：`predicted_class, scenario_id, question, task_types, explicitly_allowed_operating_context`。直接复用K02验证器，字段重复/非法Unicode与未知字段拒绝；上下文只接受K02两个枚举键。调用方类别和显式任务列表都是测试桩，没有分类器或任务识别器。

独立运行配置是`configs/q01_offline.json`，提示构造为`configs/q01_prompts.json`。四组共享请求、知识、生成设置、生成模板、全局3张完整卡预算和基础检查；仅改变候选检索方式与额外内容核验开关。配置只接受登记的四组控制值；本配置冻结的是离线程序协议，不填充或替代E01正式freeze待定项。

| 组 | 检索 | 内容核验 | 修订上限 |
| --- | --- | --- | --- |
| T | text | 无 | 0 |
| TV | text | 有 | 1 |
| G | graph | 无 | 0 |
| GV | graph | 有 | 1 |

## 调用顺序与预算（先定规则后执行）

1. 验证五字段请求和独立配置。CLI先独占预留新输出文件，避免已有文件/悬空符号链接触发任何工作。
2. K02检索一次；构造器/加载失败也计为一次检索尝试。保留K02原状态、原结果和路径。
3. 合法空结果直接停止，不调用provider；生成固定服务提示，与最终答案分开。
4. 有卡时调用generate一次，保存草稿；基础schema/引用检查一次。失败立即阻断，不用修订修补基础失败。
5. T/G至此作发布判定，绝不调用verify或revise，也不标为完成内容核验。
6. TV/GV调用verify一次。报告无问题则不修订；报告有问题时调用revise最多一次，重新基础检查；基础检查成功后再调用verify一次。复核仍有问题或服务失败即停止，无第二次修订。

| 路径 | retrieval | generate | basic_check | verify | revise |
| --- | --- | --- | --- | --- | --- |
| 非法输入/配置 | 0 | 0 | 0 | 0 | 0 |
| 合法空/未覆盖/检索失败 | 1 | 0 | 0 | 0 | 0 |
| T/G有卡正常 | 1 | 1 | 1 | 0 | 0 |
| TV/GV无内容问题 | 1 | 1 | 1 | 1 | 0 |
| TV/GV修订且基础重检成功 | 1 | 1 | 2 | 2 | 1 |

各调用在执行前计数，异常也消耗预算。修订后基础失败时不调用第二次verify。没有自动重试、新检索、补证据、外部知识或循环直到通过。修订后verify计入独立调用及实测耗时；真实token/费用未提供，不能称零成本模型调用。

## 资料隔离与载荷

运行时不读取evaluation目录、主计划、审核报告或历史问题/排名。模块导入只导入代码，不实例化Retriever或读取题集。真实K02只读取自己登记的六个知识文件，不扫描相邻资料。

生成载荷只含：五字段合法请求；登记情景的类别语义、独立假设、已知设定、未知、适用范围、不能推断事项；本次实际返回的完整证据卡；共同的指令/schema与离线生成设置。核验载荷在同一基底上增加当前候选；修订再增加该次核验报告。报告、草稿属于本次流程派生文本，不能附带外部资料。四组生成模板不暴露组名或评价身份。

“完整卡”在生成接口中定义为K01 `evidence.csv`全部原字段加`source`全部登记字段，逐值保留：短原文、agent英文概括、中文释义、modality、条件、限制、出处/页码/来源取得限制等均不截断。K02附加的rank/score/relation_paths属于检索诊断，保留于运行记录`retrieval`与`returned_cards`；不进入生成载荷，也不以候选路径携入未返回卡。情景的supporting_evidence_ids不进入生成上下文。只有本次返回的evidence_id可引用。

全局top_k固定3，无任务配额、补位或文本截断。实际卡数可能少于3；同样卡数上限不等于实际文本等长。记录生成载荷字符数和UTF-8字节数；token未知。分数只是文本相似度，不能称根因概率或事实支持。

字段白名单不能识别自由文本中所有伪装答案或恶意前提；本轮隔离证明依赖显式文件入口与字段投影，不能称全面语义防泄漏。

## 输出schema与程序判定

候选对象必须恰有三个字段：非空`answer`字符串、非空无重复`citations`字符串列表、`evidence_sufficiency`为`sufficient/partial/insufficient`。方括号内容保留作内联引用语法，必须出现在citations中；citations必须来自本次返回集合。基础检查只证明schema和引用成员资格，`semantic_support`始终不因此变成已支持。

核验对象必须恰有`verdict`与`issues`：pass对应空列表，issues对应至少一项非空字符串。缺字段、自报pass带问题、错误schema、异常均阻断；程序仍须结合基础检查、预算、调用成功和核验结果决定状态。即使核验报告pass，本轮状态也只叫`completed_verified_synthetic`，`semantic_support=not_established`。

检索状态为`partial_task_coverage`时，原任务覆盖限制必须保留到最终状态；provider自报`sufficient`或合成核验pass都不能消除它。通过组内相应检查的候选可以受限发布，但顶层仍为`evidence_insufficient`，另有`service_message`提示部分任务没有返回证据。草稿/修订的原sufficiency不改写，原K02状态与per_task保留；不补卡、不重新检索。此规则保留已知的任务覆盖边界，不把任务标签或检索分数当成真实语义支持判据。

| 状态 | 最终答案发布 | 说明 |
| --- | --- | --- |
| completed_unverified | 可 | T/G结构与引用合法；内容未核验，离线合成输出 |
| completed_verified_synthetic | 可 | 合成报告未留问题；不代表真实语义支持 |
| evidence_insufficient | 视分支 | 合法空或候选insufficient：不发布答案，仅service_message；候选partial或检索partial_task_coverage：经相应检查后可发布受限候选，仍记录不足 |
| knowledge_not_covered | 否 | K02有效未覆盖，展示固定service_message，不属于服务故障 |
| invalid_input / invalid_config | 否 | 输入或配置拒绝，不检索/生成 |
| retrieval_failed | 否 | 加载、检索异常、未知状态、不一致/不完整卡，不能包装为合理弃答 |
| generation_failed / revision_failed | 否 | provider异常或不可记录结果 |
| schema_failed / citation_failed | 否 | 原草稿/修订保留，合法证据保留 |
| verification_failed | 否 | 核验异常/schema失败，不降级发布未核验草稿 |
| content_issues_remaining | 否 | 一次修订后仍有问题，不再重写 |
| input_or_setup_failed | 否 | CLI文件/JSON/脚本初始化失败，或注入provider身份无法安全记录；仍保存适用哈希、身份诊断、零调用与未知计量 |

`publishable`只指`final_answer`是否可作为本轮离线候选展示，不等于真实模型/网页/服务质量。失败的draft、revisions、provider_trace供研究诊断，不能显示为通过答案，也不能用草稿诊断分冒充最终服务分。无卡时`final_answer=null`且`publishable=false`，`service_message`可说明不足；这和retrieval_failed的原因严格分开。

## 完整运行记录与文件写入

记录规范JSON请求哈希（键排序、ASCII转义、紧凑编码）；CLI另存原始请求文件SHA-256。无法解析时规范请求哈希明确unknown，原字节可读仍计算文件哈希。记录代码、K01校验器、K02代码、知识预期哈希与实际检索版本/index/config身份、Q01配置/提示文件及provider脚本身份；完整检索结果、卡、草稿、检查、核验、修订、实际provider载荷及哈希、调用次数、最终状态和原因均保留。

注入边界只接受原生JSON树：dict/list、字符串键、有限JSON标量且无循环；tuple、set、Path、自定义容器及非有限数拒绝。正常JSON元数据逐值保留，经JSON快照脱离注入对象，不调用其deepcopy钩子。配置不可记录返回`invalid_config`；provider身份不可记录或已声明getter失败返回`input_or_setup_failed`，均零调用。未声明可选identity仍登记为注入测试桩。检索响应不可记录返回`retrieval_failed`，计retrieval1且不调用provider。非法原值只存类型、有限表示与错误诊断，不把坏值再次装进失败封套；字符串/表示钩子异常也有安全兜底。provider输出同样先通过此边界，按对应阶段失败；最终完整记录再作严格JSON快照读回。正常路径的请求、证据、生成设置与调用预算不变。

各调用阶段用perf_counter测量耗时；未调用为null，不把未知耗时写0。token_usage/tokens为unknown；离线费用为not_applicable_offline，不伪造账单。没有真实tokenizer/价格表，也没有性能比较或平均质量分。

CLI与`write_record`使用独占`xb`，拒绝已有文件与悬空链接；父目录须已存在。参数语法错误由argparse退出2且没有结果JSON。CLI结果不能发布时退出2（包含合法不足），因此调用方必须同时检查JSON状态区分不足与失败。写满磁盘/断电等不承诺事务恢复。运行输出仅写新run，不对封存目录重跑。

## 最小使用

复用aae5103，设置`PYTHONDONTWRITEBYTECODE=1`和本轮新目录TMPDIR，不安装依赖、不读密钥。真实接线只允许本轮已预登记的K02开发输入，禁止E01真题及近义改写。

```bash
PYTHONDONTWRITEBYTECODE=1 python scripts/q01_flow.py \
  --request runs/k02/20261024_135147_4d6ea8a8/inputs/inspection.json \
  --group T --script runs/q01/20261025_010145_1392433c/smoke/cli_script.json \
  --output runs/q01/<新建目录>/<不存在的输出名>.json
```

上述固定脚本只适配已登记烟测输入及T组，不能当作任何问题的答案模板。烟测脚本`smoke/smoke_probe.py`会从当次返回卡绑定引用，生成抽象接线占位说明，验证T/GV各一次；不是正式四组问答实验。合成测试须将两份已封存抽象期望原样复制到新输出目录，再显式设置`Q01_RUN_DIR`；测试输出均在该目录，不使用默认系统临时目录。例如从项目根目录执行（新目录名自行选择且必须不存在）：

```bash
export PYTHONDONTWRITEBYTECODE=1
export Q01_RUN_DIR="$PWD/runs/q01/<新的唯一目录名>"
mkdir -p "$Q01_RUN_DIR/synthetic" "$Q01_RUN_DIR/tmp"
cp runs/q01/20261025_010145_1392433c/synthetic/expected_cases.json "$Q01_RUN_DIR/synthetic/"
cp runs/q01/20261025_010145_1392433c/synthetic/expected_cli_cases.json "$Q01_RUN_DIR/synthetic/"
TMPDIR="$Q01_RUN_DIR/tmp" python -m unittest discover -s tests -p test_q01_flow.py -v
```
